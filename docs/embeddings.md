# 向量化

## 接口约定

对外只暴露一个方法：embed(texts) 返回等长的向量列表。
把向量化做成接口而不是直接调 API，是为了让测试能注入假实现。

## 词袋哈希

FakeEmbedder 用 blake2b 把每个 token 哈希到一个桶，桶里累加计数。
这是一份确定性的词袋向量，不联网、不花钱、可解释。

## 归一化

向量最后除以自己的 L2 范数，空文本得到全零向量。
归一化之后，两个文本的余弦相似度就等于它们共享 token 的比例。

## 分词规则

英文、数字、下划线连着的一串算一个 token，中文按单字算一个 token。
所以「短链」这个词在词袋模型里是两个 token，语义信息会丢一部分。

## 维度参数

FakeEmbedder 的 dim 必须大于 0，默认 64，生产装配用 512。
维度越小哈希碰撞越多，不同词会被算成同一个桶。

## 确定性

同一段文本永远得到同一个向量，不会因为进程重启而改变。
这条性质让测试可以断言排序，而不是只能断言「返回了一个列表」。

## 为什么能验证排序

共享词汇越多的两段文本，余弦相似度越高，所以排序是可预期的。
测试用这一点构造「正确答案应该排第一」的用例。

## 局限性

词袋模型没有任何语义：意思相同但用词不同的两句话，相似度可能是 0。
所以它只能验证流程和排序，验证不了真实语义召回。

## OpenAI 兼容实现

OpenAIEmbedder 走 /v1/embeddings，默认模型是 text-embedding-3-small。
任何 OpenAI 兼容的接口（含各类国产模型服务）换个 base_url 就能用。

## 空输入

embed 收到空列表时直接返回空列表，不发起请求。
这一条省掉一次无意义的网络往返。
