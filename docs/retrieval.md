# 混合检索

## 向量检索

向量检索把问题和片段都编码成向量，用余弦相似度排序。
它擅长「意思相近」：问「怎么防止并发写坏数据」，能召回讲 SETNX 原子写入的片段，即使两者没有一个字相同。
默认的相似度下限是 0.15，低于它的命中会被丢掉。

## BM25 关键词检索

BM25 按词频和逆文档频率打分：一个词越罕见，命中它的文档得分越高。
它擅长精确词：型号、代码标识符、专有名词，一找一个准。
但它不理解同义改写，问「怎么防并发」不会召回只写了 SETNX 的片段。

### 中文分词策略

中文按二元切分，英文和数字按连续词切分。
这样不用引入 jieba 之类的分词依赖，又能让「短链」这类词在 BM25 里算得准。

## RRF 融合

RRF 的全称是 Reciprocal Rank Fusion，每个候选的得分等于各通道 1/(k + 名次) 之和，k 默认取 60。
两路都排第一的片段得分是 2/61，约等于 0.033。

### 为什么只融合名次

余弦相似度落在 -1 到 1 之间，BM25 是无上界的正数，两个分数量纲完全不同，直接加权相加没有意义。
RRF 只取名次，天然回避了量纲问题：不管一路的分数是 0.9 还是 30，排第一就是排第一。

### 融合分数怎么读

融合分数只能用来排序，不能当相关性阈值用。
0.033 不代表「相关度 3%」，只代表两个检索器都把它排在了第一位。

## 阈值与兜底

向量检索的 min_score 默认 0.15，关键词检索默认 0.0。
阈值调高，无命中的比例上升，但能少答错；调低则相反。
这个取舍要拿标注好的评估集来定，不能凭感觉调。

## 候选池扩展

混合检索让每个通道先取 top_k 乘以 candidate_pool 条候选，融合之后再截回 top_k，默认 3 倍。
如果每个通道只取 top_k 条，某个通道排在第 k 位的命中会在融合之前就被丢掉，
融合反而可能比单通道召回更差。这个缺陷是被评估集测出来的，不是想出来的。
