# 模型客户端

## 接口约定

LLM 接口只有一个方法：chat(prompt) 返回字符串。
和 Embedder 一样，抽象出来的唯一目的是让测试能换成假实现。

## FakeLLM 的行为

FakeLLM 会把收到的 prompt 记进 prompts 列表，再按剧本返回答案。
测试靠 prompts 断言「检索到的片段确实被拼进了提示词」。

## 剧本耗尽之后

replies 里有多条时按顺序弹出，弹到最后一条就一直返回它。
这样多轮测试不用为每一轮都准备一句台词。

## OpenAI 兼容实现

OpenAIChat 走 /v1/chat/completions，默认模型 gpt-4o-mini。
DeepSeek 之类的服务换个 base_url 和模型名即可。

## 提示词模板

模板要求严格依据资料回答、不要编造、资料不足时直说，并保留 context 与 question 两个占位符。
约束写在模板里而不是代码里，改话术不用改逻辑。

## 为什么不做流式

当前版本先把整条链路跑通，同步返回完整字符串。
流式要改接口签名和前端消费方式，属于工程层的优化，不是这一层的核心。

## 为什么强制编号引用

要求模型用 [1] [2] 标注依据，编号必须对应资料列表。
这样答案里的每句话都能回到具体片段核对，是 RAG 敢用的前提。
