# 向量存储

## 表结构

chunks 表有六个字段：自增主键 id、source、heading、ordinal、text 和 vector。
source 上建了索引，删除某个来源时不用全表扫。

## 为什么向量存 BLOB

向量用 np.float32 转成 bytes 存进 BLOB 字段。
SQLite 没有原生的数组类型，转成二进制比存 JSON 字符串省一半以上空间，读出来也不用解析。

## 归一化

写入和查询的向量都先做 L2 归一化，范数为 0 的向量把范数当成 1，避免除零。
归一化之后，点积就等于余弦相似度，不需要每算一次再除一次模长。

## 余弦相似度

检索时把库里所有向量堆成一个矩阵，和查询向量做一次矩阵乘法得到全部得分。
这是全量精算，不是近似最近邻，所以结果是精确的 top-k。

## top-k 取法

得分用 argsort 取负值排序，再切前 top_k 个。
这样得到的顺序是按相似度降序，第一名的索引是 0。

## 维度校验

查询向量的维度必须和库内一致，否则直接抛 ValueError 并带上两个维度值。
维度对不上通常是换了 embedding 模型但没重建索引，报出来比默默算错强。

## top_k 校验

top_k 小于等于 0 会抛 ValueError。
这条校验挡的是「以为 top_k=0 表示不限量」这种误解。

## 幂等导入

同一 source 重复导入时先调 delete_source 删掉旧片段再写入。
否则同一份文档导入两次，库里会有两份片段，检索结果里会出现重复来源。

## 供关键词检索取数

iter_chunks 按写入顺序返回全部片段，BM25 每次检索前用它重建索引。

## 内存模式

VectorStore 默认用 :memory:，进程退出数据就没了。
这个取舍是为了测试隔离：每个测试一个独立库，结果只取决于测试自己。

## 连接参数

sqlite3.connect 带 check_same_thread=False，允许连接在多个线程间共享。
FastAPI 的同步端点跑在线程池里，不加这个参数会报跨线程错误。
